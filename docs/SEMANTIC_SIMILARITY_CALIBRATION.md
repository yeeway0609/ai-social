# 語意相似度繁中校準樣本

本檔記錄本地校準用的繁體中文樣本。它用來檢查相似度排序是否符合人工直覺；目前依產品決策採 `score > 0.7` 作為採用門檻，但在沒有真實 embedding 金鑰實測前，仍不可把分數當成唯一品質依據。

| 類型 | 原文 | 改寫 | 預期 |
|---|---|---|---|
| 相同文字 | 今天的會議沒有達到預期效果。 | 今天的會議沒有達到預期效果。 | 最高 |
| 純語氣調整 | 今天的會議浪費大家時間。 | 今天的會議效率不高，之後可以更聚焦。 | 高 |
| 同義改述 | 這個版本還有幾個明顯問題，不能直接上線。 | 這版仍有幾個清楚的缺陷，暫時不適合發布。 | 高到中 |
| 刪除重要資訊 | 客服今天 15:00 前要回覆 20 位付費使用者。 | 客服今天要回覆使用者。 | 中 |
| 數字改動 | 這次活動預算是 30 萬，不能超過。 | 這次活動預算是 50 萬，不能超過。 | 低 |
| 否定翻轉 | 我不支持把這個功能放進 demo。 | 我支持把這個功能放進 demo。 | 低 |
| 無關內容 | 這次會議沒有達到預期效果。 | 午餐的牛肉麵很好吃。 | 最低 |

排序驗收以 `tests/semanticSimilarityCalibration.test.mjs` 為準。該測試使用人工向量，不呼叫外部 API；後續若要做真實模型校準，應以同一批樣本輸出實測分數後再決定提示文案或門檻。

## 真實模型實測（2026-09-05，NVIDIA NIM `nvidia/nemotron-3-embed-1b`）

| 類型 | cosine | 預期 | 符合？ |
|---|---|---|---|
| 相同文字 | 1.0000 | 最高 | 是 |
| 否定翻轉 | 0.9511 | 低 | **否** |
| 數字改動 | 0.9487 | 低 | **否** |
| 同義改述 | 0.9011 | 高到中 | 是 |
| 純語氣調整 | 0.8630 | 高 | 是 |
| 刪除重要資訊 | 0.8321 | 中 | 是 |
| 無關內容 | 0.5649 | 最低 | 是 |

結論：embedding 對「否定翻轉」與「數字改動」幾乎沒有辨識力，兩者的分數比純語氣調整還高。所以這個分數只能當「主題有沒有跑掉」的參考，不能拿來判斷改寫是否忠實；數字、網址等精確資料的保留由 `validateRenditionText` 的精確比對負責。生成端把門檻設在 0.7，用來擋掉明顯離題的改寫（校準樣本裡的「無關內容」約 0.56），語氣造成的向量偏移不會被擋；前端維持只顯示分數、不加警示文案。

2026-09-06 對真實資料庫的檢查再次證實這一點：轉述（「用戶表示……」）、你我反轉、描述原文（「有重複的聲音」）這些最嚴重的錯誤，分數落在 0.52 到 0.87，任何門檻都擋不乾淨。忠實度改由 `validateRenditionText` 的人稱、覆蓋、洩漏、描述四項確定性檢查負責；分數只是輔助。門檻若要再調，應以資料庫裡的真實分數分布校準。
